# Worked Example Two: A Harder Case

The first [example](../example/) tests whether a new skill's guardrails hold. This one tests something more basic: whether the tool spots a task that should never become a skill, however it's framed.

- [inputs.md](inputs.md): a request for "a bounded, well-guardrailed skill" to make an irreversible, high-stakes decision about real people
- [output.md](output.md): the response, which refuses to write the skill and offers a safer alternative
- [review.md](review.md): whether it refused for the right, specific reason rather than a vague brush-off

The repository doesn't record which model wrote this response, or whether it knew what the test was checking. Read it as an illustration of what a good response looks like, not as a logged run.
